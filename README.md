# Система мониторинга и управления поливом зеленых зон

Учебная программная система для мониторинга влажности почвы, базового контроля газовой обстановки и поддержки решений по поливу.

## Что умеет система
- собирает измерения влажности по зонам;
- анализирует состояние зоны относительно нормативов;
- поддерживает добавление и удаление датчиков;
- ведет журнал событий в файл `logs/app.log`;
- учитывает газовые датчики (необязательные, могут стоять только на части территорий);
- предупреждает, если обнаружена вероятность запаха газа.

## Логика работы

### 1) Анализ полива
Для каждой зоны система:
1. читает измерения влажности;
2. получает нормативы (`min_moisture`, `max_moisture`) по типу растений;
3. вычисляет среднюю влажность;
4. формирует статус:
   - `Требуется полив` — ниже минимума;
   - `Норма` — в диапазоне;
   - `Переувлажнение` — выше максимума;
   - `Ошибка данных` — нет измерений.

### 2) Анализ газа
Если в зоне есть газовый датчик (`sensor_type='gas'`), используется пиковое значение `gas_ppm`:
- `< 600 ppm` — `Газовая норма`;
- `600..899 ppm` — `Есть вероятность запаха газа`;
- `>= 900 ppm` — `Высокая вероятность запаха газа`.

Если газовых датчиков в зоне нет, выводится статус `Нет газовых датчиков`.

### 3) Общий статус зоны
Общий статус строится из результата по влажности и газу.
Пример: `Норма + Проверить газ`.

## Нюансы добавления и удаления датчиков

### Добавление датчика
Используйте `services.sensor_service.add_sensor(zone_id, sensor_type, location_note)`.

- `sensor_type`:
  - `moisture` — датчик влажности;
  - `gas` — датчик газа.
- `location_note` — текстовое описание места установки (опционально).

После создания датчика можно записать данные через
`add_measurement(sensor_id, moisture=..., gas_ppm=...)`.

**Важно:**
- для `moisture` обычно заполняется только `moisture`;
- для `gas` обычно заполняется только `gas_ppm`.

### Удаление датчика
Используйте `remove_sensor(sensor_id)`.

Что происходит:
1. сначала удаляются все измерения датчика из `measurements`;
2. затем удаляется запись о датчике из `sensors`.

Возвращаемое значение:
- `True` — датчик найден и удален;
- `False` — датчик с таким ID не найден.

## Логирование
Логи пишутся в консоль и дублируются в файл:
- `logs/app.log`

В журнал попадают:
- информационные записи по зонам;
- ошибки по отсутствующим данным/нормативам;
- предупреждения о вероятности запаха газа.

## Подготовка демо-данных
```bash
python src/init_demo_data.py
```

В демо:
- есть 3 зоны;
- газовые датчики установлены **не на всех** участках (только на некоторых территориях);
- добавлены примеры нормальных и предупреждающих газовых значений.

## Первичная проверка работоспособности

### Автотесты
```bash
python -m unittest discover -s tests -v
```

Покрыто:
- добавление/удаление датчика;
- запись/чтение измерений;
- срабатывание предупреждения по газу.

### Быстрая ручная проверка
1. Инициализировать демо-данные.
2. Запустить `src/main.py`.
3. Убедиться, что в `logs/app.log` появились записи по всем зонам.
4. Для зоны с газовым датчиком и `gas_ppm >= 600` должен появиться предупреждающий статус.
